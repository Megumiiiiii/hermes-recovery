Tenang dulu: apa yang aman dan di mana

30 detik membaca, biar nggak panik dan salah urutan

Yang hilang kalau VPS mati: mesinnya, IP-nya, dan file yang belum pernah di-backup. Yang tidak hilang: memori, skill, riwayat percakapan, konfigurasi, kredensial bot, seluruh kode proyek — semuanya ada di Google Drive, folder hermes-vps-backup.

File di DriveIsinyaFrekuensi
daily/hermes-brain-*.tar.gz config, .env, token OAuth, memories, skills, cron, plugins, sessions, semua profil, snapshot DB, unit systemd, config Cloudflare Tunnel, dump pm2, nginx harian
daily/projects-*.tar.gz semua repo & aset kecil (33 direktori), tanpa node_modules/venv/cache harian
weekly/assets-*.tar.gz aset besar: beatmap, apk-share, rpgm-port Senin
💡 Aturan emas: restore dari tarball terbaru dulu, baru nyalakan service. Jangan menyalakan gateway sebelum state.db ditaruh di tempatnya — kalau tidak, Hermes membuat DB kosong dan backup lama jadi tidak relevan.

Yang wajib kamu simpan di luar VPS (kit darurat)

Ini bagian yang sering terlewat: untuk mengunduh backup, kamu butuh akses ke Drive-nya sendiri. Simpan tiga hal ini di PC atau password manager:

  1. rclone.conf — berisi token Drive. Tanpa ini kamu harus otorisasi ulang.
  2. client_id + client_secret OAuth — untuk bikin remote baru kalau perlu.
  3. Akses akun Google pemilik Drive + kode SSH/console VPS baru.
1

Siapkan VPS baru

spesifikasi, zona waktu, dan satu pengaturan yang wajib dimatikan

Spesifikasi minimum: Ubuntu 22.04/24.04/26.04, 2 vCPU, 4 GB RAM (8 GB lebih nyaman), disk ≥ 60 GB. Pilih lokasi yang dekat (Singapore/Jakarta) supaya latensi ke Telegram rendah.

# 1. update dasar
sudo apt update && sudo apt -y upgrade
sudo apt -y install curl unzip git sqlite3 nginx jq python3-pip

# 2. zona waktu (penting: cron backup pakai jam WIB)
sudo timedatectl set-timezone Asia/Jakarta
timedatectl | grep "Time zone"
⚠️ Matikan IPv6. Di box lama, IPv6 membuat gateway hang dan CPU melonjak ke 95%. Lakukan sekarang, sebelum Hermes dipasang:
sudo tee /etc/sysctl.d/99-disable-ipv6.conf >/dev/null <<'EOF'
net.ipv6.conf.all.disable_ipv6 = 1
net.ipv6.conf.default.disable_ipv6 = 1
net.ipv6.conf.lo.disable_ipv6 = 1
EOF
sudo sysctl --system

# pastikan IPv6 benar-benar mati (harus kosong)
ip -6 addr show scope global

Setelah itu pastikan kamu bisa SSH ke VPS baru dengan IPv4:

ssh ubuntu@<IP-VPS-BARU>
💡 Kalau provider memberi login sebagai root, buat user ubuntu dan salin authorized_keys — semua path di panduan ini memakai /home/ubuntu.

Install Hermes (kosong dulu, jangan setup apa-apa)

konfigurasi asli akan datang dari backup, bukan dari wizard
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
exec "$SHELL" -l          # muat ulang PATH
hermes --version
⚠️ Jangan menjalankan hermes setup atau memilih model dulu. Kalau kamu setup, Hermes membuat config.yaml baru — nanti menimpa config hasil restore dan semua provider/fallback hilang.

Yang perlu ada setelah langkah ini:

  • ~/.local/bin/hermes (atau /usr/local/bin/hermes)
  • ~/.hermes/ — direktori home Hermes, masih kosong
3

Install rclone & buka akses ke Drive

gerbang ke seluruh backup
curl -sLO https://downloads.rclone.org/rclone-current-linux-amd64.zip
unzip -oq rclone-current-linux-amd64.zip
sudo cp rclone-*-linux-amd64/rclone /usr/local/bin/
sudo chmod +x /usr/local/bin/rclone
rclone version | head -1

Cara A — kamu punya kit darurat (paling cepat)

Salin rclone.conf dari PC ke VPS baru:

mkdir -p ~/.config/rclone
scp rclone.conf ubuntu@<IP-VPS-BARU>:~/.config/rclone/rclone.conf
chmod 600 ~/.config/rclone/rclone.conf
rclone about gdrive:      # harus muncul Total/Used/Free

Cara B — bikin remote baru dengan client_id sendiri

rclone config create gdrive drive scope=drive \
  client_id "<CLIENT_ID>" client_secret "<CLIENT_SECRET>" \
  config_is_local=true --non-interactive

rclone akan mencetak link 127.0.0.1:53682/auth?state=…. Di PC kamu, buka tunnel lalu buka link itu di browser:

ssh -N -L 53682:127.0.0.1:53682 ubuntu@<IP-VPS-BARU>
# lalu buka link dari output rclone di browser PC, login, Allow

Cara C — darurat, tanpa client_id

Pakai client bersama milik rclone (masih hidup sampai akhir 2026):

rclone config create gdrive drive scope=drive \
  config_shared_client_id=true config_is_local=true --non-interactive
✅ Cek berhasil: rclone lsf gdrive:hermes-vps-backup/ harus menampilkan daily/ dan weekly/.
4

Restore "otak" — ini langkah paling penting

memori, skill, kredensial, DB, dan semua profil
mkdir -p ~/restore && cd ~/restore
F=$(rclone lsf gdrive:hermes-vps-backup/daily/ | grep '^hermes-brain-' | sort | tail -1)
echo "ambil: $F"
rclone copy "gdrive:hermes-vps-backup/daily/$F" ./

# taruh ke tempatnya (config, bin, .config, .cloudflared, .pm2, .hermes/*)
tar xzf "$F" -C ~
ls ~/.hermes | head

4a. Kembalikan database tiap profil

Di dalam tarball, DB disimpan sebagai snapshot konsisten (bukan file mentah yang bisa korup). Nama filenya memuat profilnya:

cd ~/restore/db
ls                 # hermes_state.db-*.sqlite, hermes_profiles_aino_state.db-*.sqlite, dst.

cp hermes_state.db-*.sqlite ~/.hermes/state.db

for f in hermes_profiles_*_state.db-*.sqlite; do
  p=$(echo "$f" | sed -E 's/^hermes_profiles_(.*)_state\.db-.*/\1/')
  mkdir -p ~/.hermes/profiles/$p
  cp "$f" ~/.hermes/profiles/$p/state.db
  echo "restore profil: $p"
done

# wajib: cek integritas sebelum dipakai
sqlite3 ~/.hermes/state.db 'PRAGMA integrity_check;'
✅ Hasil integrity_check harus ok. Kalau malformed, pakai tarball tanggal sebelumnya — jangan dipaksa.

4b. Kunci izin file (jangan dilewat)

chmod 600 ~/.hermes/.env ~/.hermes/auth.json ~/.config/rclone/rclone.conf
chmod 700 ~/.hermes/shared 2>/dev/null
ls -l ~/.hermes/.env ~/.config/rclone/rclone.conf

4c. Pulihkan cron backup

crontab ~/restore/env-*/crontab.txt
crontab -l | tail -3     # harus ada baris hermes-gdrive-backup.sh 30 3 * * *

4d. Pulihkan infra: nginx, unit systemd, Cloudflare Tunnel

# nginx (reverse proxy webapp/dashboard)
sudo tar xzf ~/restore/env-*/etc-nginx.tar.gz -C /
sudo nginx -t && sudo systemctl reload nginx

# unit systemd tingkat sistem (tunnel, pm2, dsb.)
sudo tar xzf ~/restore/env-*/etc-systemd-system.tar.gz -C /
sudo systemctl daemon-reload

# lihat unit apa saja yang perlu dinyalakan
cat ~/restore/env-*/systemd-system-units.txt | grep -E 'hollow|pm2|tunnel'
⚠️ Cloudflare Tunnel butuh file kredensial di ~/.cloudflared/ (ikut terestore) plus paket cloudflared. Tanpa paketnya, unit tunnel akan gagal dengan error 1033.
curl -fsSL -o /tmp/cloudflared.deb \
  https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64.deb
sudo dpkg -i /tmp/cloudflared.deb
cloudflared --version
ls ~/.cloudflared/*.yml

Restore kode & aset

repo, proyek bot, dan file besar

rclone copy "gdrive:hermes-vps-backup/daily/$P" ./

Aset besar (beatmap, apk, port game) hanya ada di folder weekly/. Ambil kalau perlu:

A=$(rclone lsf gdrive:hermes-vps-backup/weekly/ | grep '^assets-' | sort | tail -1)
rclone copy "gdrive:hermes-vps-backup/weekly/$A" ./
tar xzf "$A" -C ~
💡 Isi tarball kode tidak termasuk node_modules, venv, dan build output. Setelah restore, jalankan npm install / pip install -r requirements.txt di proyek yang mau dinyalakan.
6

Nyalakan service

pm2, gateway, dan unit user

6a. pm2 (proses bot & worker)

# kalau pm2 belum ada
npm i -g pm2

# dump pm2 ikut terestore di ~/.pm2/dump.pm2
pm2 resurrect
pm2 list
pm2 save

# kalau box ini memakai unit pm2-ubuntu.service (ikut terestore di langkah 4d)
sudo systemctl enable --now pm2-ubuntu

6b. Gateway Hermes (systemd user)

loginctl enable-linger ubuntu
systemctl --user daemon-reload
systemctl --user enable --now hermes-gateway.service
systemctl --user status hermes-gateway.service --no-pager | head -15
💡 Unit hermes-gateway.service ada di dalam tarball otak (~/.config/systemd/user/). Kalau unit lain seperti watchdog ikut ter-enable tapi biner-nya belum ada, matikan dulu: systemctl --user disable --now <unit>.

6c. Cek port yang seharusnya hidup

cat ~/restore/env-*/ports-and-services.txt | head -20
ss -ltnp | grep -E '9120|20128|3002'

8

Kalau ada yang gagal

gejala → penyebab → perbaikan
GejalaPenyebab & perbaikan
invalid_grant / “refresh session revoked” Token Drive dicabut. rclone config reconnect gdrive: lalu otorisasi ulang (tunnel SSH ke port 53682).
hermes: command not found PATH belum dimuat: exec "$SHELL" -l, atau pakai ~/.local/bin/hermes.
Gateway mati berulang, CPU 95% IPv6 masih hidup. Ulangi langkah 1 (sysctl disable ipv6) lalu reboot.
state.db was replaced underneath DB diganti saat gateway hidup: systemctl --user restart hermes-gateway.
port already in use ss -ltnp | grep <port>, matikan proses lama atau ganti port di config.
Proses dibunuh (OOM) Tambah swap: sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile.
Cloudflare error 1033 Unit tunnel jalan tapi cloudflared belum terpasang, atau file ~/.cloudflared/*.json tidak ikut terestore.
pm2: command not found npm i -g pm2, lalu pm2 resurrect.
Telegram “polling conflict” Dua gateway memakai token yang sama. Matikan salah satu (platforms.telegram.enabled: false + hapus TELEGRAM_* dari .env box kedua).
Unknown provider / 401 saat turn Provider custom wajib ditulis custom:<slug>, dan key-nya harus ada di .env profil yang dipakai — bukan di shell.
Restore DB malformed Pakai tarball tanggal sebelumnya (sort | tail -2 | head -1). Snapshot lama tetap valid.

Kalau Drive pun tidak bisa diakses

Ini skenario terburuk (akun Google kena suspend). Yang menyelamatkan: salinan lokal yang kamu unduh berkala ke PC. Minimal sebulan sekali:

rclone copy gdrive:hermes-vps-backup/weekly ~/unduhan/hermes-backup-weekly --max-age 40d
